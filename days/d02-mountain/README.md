# D2 - mountain

## 명세

### 목적
배열을 stride 간격으로 되풀이해 읽는 처리량(MB/s)을, 작업 집합 크기와 stride를 바꿔 가며 재는 도구. 결과로 이 머신의 메모리 계층(L1·L2·L3·DRAM)을 눈으로 본다.
크기 축은 시간 지역성을, stride 축은 공간 지역성을 보여 준다(CSAPP 6.6.1 메모리 마운틴). 결과 CSV로 3D 그래프를 그리고, 능선이 꺾이는 크기를 `lscpu`의 캐시 크기와 대조한다.
여기서 만드는 측정 방법(데우기, 반복 횟수 늘리기, `black_box`)은 D5 disk-model과 D7 blocking에서 다시 쓴다. D32 tlb에서는 이 코드를 라이브러리로 떼어 TLB 계단을 잰다.
Rust로는 `Vec`의 소유권, `&[T]` 슬라이스로 빌려주기, `Instant`·`Duration`, `std::hint::black_box`, release와 debug 빌드의 차이를 익힌다.

### 사용법
```
mountain [-M <최대 크기>] [-S <최대 stride>]
```
- `-M`: 가장 큰 작업 집합(바이트). 10진수이고, 뒤에 `K`(×1024)나 `M`(×1024²)을 붙일 수 있다. 2의 거듭제곱이어야 하고 16K ≤ 값 ≤ 256M. 기본 256M
- `-S`: 가장 큰 stride(원소 단위, 원소 하나는 8바이트). 10진수 1~64. 기본 16
- 옵션 순서는 자유다. 같은 옵션을 두 번 주면 마지막 값을 쓴다. 옵션 바로 뒤의 인자는 `-`로 시작해도 모르는 옵션(E2)이 아니라 그 옵션의 값이다(D1과 같다). `-`를 떼지 않고 그대로 해석한다: `-S -1`의 값은 `-1`이고, 정수가 아니므로 E3 오류다
- 측정은 release로 한다: `cargo run --release -p mountain > days/d02-mountain/results/mountain.csv`

### 기능
- F1. 인자를 해석한다(`-M`, `-S`, 기본값).
- F2. `u64` 원소 M/8개짜리 `Vec`을 **한 번만** 만들고, **모든 원소에 0이 아닌 값을 써 넣는다**. 크기 n은 이 배열의 앞부분 슬라이스 `&data[..n/8]`로 잰다. 복사하지 않는다.
- F3. `read_stride(data, k)`는 `data[0]`, `data[k]`, `data[2k]`, …(인덱스 < 길이)를 읽어 합을 돌려준다. 합이 넘치면 2^64로 감는다(wrapping).
- F4. `throughput(data, k)`는 한 칸을 이렇게 잰다.
  1. 데우기: `read_stride`를 한 번 부른다(재지 않음).
  2. 반복 횟수 r = 1에서 시작한다. `read_stride`를 r번 연달아 부른 시간이 10ms 이상이 될 때까지, r을 두 배로 늘려 다시 잰다.
  3. 처리량(MB/s) = r × (읽은 원소 수 × 8) ÷ 걸린 초 ÷ 10^6. 읽은 원소 수는 ⌈길이 ÷ k⌉이고, 1MB = 10^6바이트다(CSAPP와 같다).
  4. 컴파일러가 읽기를 지우거나 반복 밖으로 빼지 못하게, `read_stride`에 넘기는 슬라이스와 돌려받는 합을 둘 다 `std::hint::black_box`에 통과시킨다.
- F5. 크기 16K, 32K, 64K, …, M(두 배씩) × stride 1~S의 모든 칸을 재서 아래 CSV로 쓴다.

### 출력 형식
```
size,s1,s2,…,s<S>
16384,<MB/s>,<MB/s>,…
32768,…
…
<M>,…
```
- 첫 줄은 머리줄이다. 그다음 크기마다 한 줄씩, 작은 크기부터 쓴다. 줄 수는 log2(M ÷ 16K) + 1이다(기본 15줄)
- `size`는 바이트(10진수)다. 나머지 칸은 MB/s를 반올림한 정수(`{:.0}`)이고 0보다 크다
- 표준 에러는 비어 있다(진행 표시도 쓰지 않는다)

### 출력 예시 (참조 구현으로 확인. 숫자는 실행마다 다르다)
```
$ target/release/mountain -M 64K -S 4
size,s1,s2,s3,s4
16384,16292,16981,17152,17137
32768,17188,17245,17147,17017
65536,17379,17363,17011,16674
```
참조 구현의 기본 실행(256M × 16)은 이 머신에서 약 7초 걸렸고, 최대 RSS는 약 258MiB였다(`/usr/bin/time -v`).

### 오류 처리 (잘못된 입력에 패닉 금지)
모든 오류는 표준 에러에 `mountain: `으로 시작하는 한 줄을 쓰고 종료 코드 1로 끝난다. 표준 출력은 비어 있다. 아래 메시지는 예시이고, 굵게 적은 맥락은 꼭 담는다(PRINCIPLES 2-3).
- E1. 사용법: 옵션이 아닌 인자(`foo`, `16K`) → **`usage`**
  - 예: `mountain: usage: mountain [-M <size>] [-S <stride>]`
- E2. 옵션: 모르는 옵션(`-x`, `-m`, `-s`, 그 밖에 `-`로 시작하는 모든 인자), 옵션 뒤에 값이 없음 → **그 옵션 이름**
  - 예: `mountain: unknown option '-m'`, `mountain: -S needs a value`
  - UTF-8이 아닌 옵션 이름은 `to_string_lossy`처럼 바꿔 써도 된다
- E3. 값: 정수가 아님, 모르는 접미사(`1G`, 소문자 `1k`), 타입에 안 들어감, 곱하다 넘침(`18014398509481984K`), 2의 거듭제곱이 아님, 범위 밖(`-M 8K`, `-M 512M`, `-S 0`, `-S 65`), UTF-8이 아님 → **옵션 이름과 받은 값 그대로**(UTF-8이 아니면 옵션 이름만)
  - 예: `mountain: -M: invalid size '24K' (power of two, 16K..256M)`, `mountain: -S: invalid stride '65' (1..64)`
- E4. 출력 실패(`mountain -M 16K -S 1 > /dev/full`) → `mountain:`으로 시작하는 메시지
- 오류가 여럿 겹치면 어느 것을 보고해도 된다. check.sh는 한 번에 하나만 넣는다

### 제약
- std만 쓴다. 외부 크레이트와 unsafe는 쓰지 않는다
- 인자는 `std::env::args_os`로 받는다(D1과 같다)
- 측정 코드는 `src/measure.rs` 모듈에 둔다. 공개 API는 아래와 같다
  ```rust
  /// data[0], data[stride], data[2 * stride], …를 읽어 합을 돌려준다.
  /// 합은 넘치면 감는다(wrapping). stride ≥ 1이라고 가정한다(검사는 부르는 쪽이 한다).
  pub fn read_stride(data: &[u64], stride: usize) -> u64;
  /// data를 stride 간격으로 읽는 처리량(MB/s)을 F4의 방법으로 잰다. stride ≥ 1이라고 가정한다.
  pub fn throughput(data: &[u64], stride: usize) -> f64;
  ```
  확장(`-u`)을 하면 공개 함수를 더해도 된다
- 같은 파일의 `#[cfg(test)] mod tests`에 `read_stride`를 검사하는 `#[test]`를 3개 이상 둔다: stride 1, 길이를 나누지 않는 stride(마지막 원소가 읽히는 경우), 넘침(`u64::MAX`가 든 배열). `cargo test`는 debug 빌드로 돈다는 점을 기억한다
- 배열(`Vec`)은 `main` 쪽에서 한 번 만들어 소유하고, 측정 함수에는 슬라이스로 빌려준다. 크기마다 새로 할당하거나 복사하지 않는다
- 오류 종류는 enum으로, 메시지는 `Display` 한 곳에서 만든다(PRINCIPLES 2-2). 출력은 `writeln!`으로 쓰고 끝에서 `flush`한다(PRINCIPLES 5-2)

### 완료 기준
```sh
./days/d02-mountain/check.sh
```
- 마지막 줄이 `FAIL 0`이고 종료 코드가 0이면 완료다. check.sh는 `--release`로 빌드하고, 기본 실행(참조 구현으로 약 7초)을 한 번 포함한다
- 처리량은 실행마다 달라서 숫자를 그대로 비교하지 않는다. 대신 CSV 모양(머리줄, 행 수, 크기 열, 양의 정수), 빈 표준 에러, 종료 코드를 본다. 그리고 기본 실행(256M × 16)에서 세 가지를 본다
  - 시간 지역성: s8 열에서 16KB 행 ÷ 256MB 행 ≥ 3. stride 8 = 64바이트라 읽을 때마다 새 블록이다. 책도 시간 지역성 능선을 stride 8 단면으로 보여 준다
  - 공간 지역성: 256MB 행에서 s1 ÷ s16 ≥ 3
  - 기본 실행 시간 ≤ 20초. 실행 하나가 40초를 넘으면 끊고 FAIL로 센다
  - 문턱은 참조 구현을 이 머신에서 세 번 재서 넉넉하게 잡았다(시간 약 7배, 공간 약 6.2~6.6배, 약 7초)
- 오류 케이스는 종료 코드 1, 빈 표준 출력, 표준 에러 첫 줄(`mountain: `으로 시작, 맥락 포함), 패닉 없음을 본다 (PRINCIPLES 6-2)
- 경계값: `-M` 16K(최소)·8K·16383·256M(기본, 최대)·512M·268435457·u64를 넘는 값·곱하다 넘치는 값 / `-S` 0·1·64·65 / 크기 행 1개(`-M 16K`)
- `cargo test -p mountain`에서 measure 모듈의 테스트 3개 이상이 통과해야 한다
- 결과물: 기본 실행의 CSV를 `days/d02-mountain/results/mountain.csv`에, 3D 그래프를 `results/mountain.png`에 두고 커밋한다. 기록에는 측정 환경(`lscpu`의 Model name, `uname -r`, `--release`)과, 능선이 꺾이는 크기를 캐시 크기와 비교한 한 줄을 쓴다. `lscpu`의 L1d 128KiB는 코어 4개의 합이고, 코어 하나의 L1d는 32KiB다

### 범위 밖
소문자 접미사(`k`, `m`), `G`, 2의 거듭제곱이 아닌 크기, 긴 옵션(`--max`), `--`, `-h`, `+` 부호, 쓰기 처리량, 여러 스레드. check.sh는 이것들을 넣지 않는다.

### 확장
- `-u`: `read_stride` 대신 4×4 언롤링 함수(한 번에 원소 4개, 누산기 4개. CSAPP 6.6.1의 `test` 함수, 5장의 기법)로 잰다. 출력 형식은 같다. 두 함수가 같은 합을 돌려주는지 테스트를 둔다. 어느 읽기 함수로 잴지 고르는 방법은 자유다(`bool` 인자, 함수 포인터 `fn(&[u64], usize) -> u64` 등). `EXT=1 ./days/d02-mountain/check.sh`로 확인하고, 언롤링 전후 처리량이 어느 영역에서 얼마나 달라지는지 기록에 쓴다
- 코어 고정: `taskset -c 3 target/release/mountain`으로 한 코어에 묶어 재고, 묶지 않았을 때와 비교한다

## 기록
- 예측: stride가 증가할수록 1/2로 떨어지다가 마지막엔 1로 고정. debug마운틴이 더 차이가 클 거 같은데, release는 최적화 많이 들어가니까
- 결과: ① 256MB 행 s1 10553 → s2 6789 → s4 3760 → s8 2359 → s16 1818 MB/s. 2배마다 0.64·0.55·0.63·0.77배로 절반보다 덜 떨어졌고, s8 뒤에도 조금 더 떨어짐(s16 ≈ s1의 1/5.8). ② -M 64M -S 16에서 16KB·s1이 debug 796, release 14246 MB/s로 debug가 약 18배 느림. debug 마운틴은 거의 평평(s8 열 16KB÷64MB가 debug 1.14배, release 6.0배). 능선(s8 열): 32K→64K 13645→9495(L1d 32KiB), 2M→4M 8345→5482(L2 2MiB), 4M→8M→16M 5482→2956→2271(L3 6MiB, 그 뒤 DRAM)
- 환경: Intel(R) N150, 6.8.0-147-generic, --release. 기본 실행 7.05초, 최대 RSS 264192KB
- 배운 것: 또다시 개많은 문법. stride 메모리 개념
- 재미(1~5): 3 - 막힌 시간(분):300+ - 힌트 단계(0~3):0
