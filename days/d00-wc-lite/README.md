# D0-일 · wc-lite

## 명세

### 목적
파일의 줄·단어·바이트 수를 세는 도구. GNU `wc`의 축소판이다.
D0 xxd-lite는 파일 하나를 읽고 끝났다. 오늘은 여러 파일 중 하나가 실패해도 나머지를 끝까지 처리하는 CLI를 만든다.
"항목 하나의 실패는 알리고 다음으로"(PRINCIPLES 2-4)는 셸(D27)과 서버(D46, 프록시)에서 그대로 다시 쓰는 구조다.
Rust로는 `struct` + `impl`, 상태를 나누는 `enum`, `Box<dyn Error>`, `mod`로 파일 나누기, `#[test]`를 익힌다.
폭을 정할 때 쓰는 파일 메타데이터(`fs::metadata`)는 CSAPP 10.6의 `stat`이다.

### 사용법
```
wc-lite [-l] [-w] [-c] <파일>...
```
- `-l` 줄 수, `-w` 단어 수, `-c` 바이트 수. 하나도 없으면 셋 다
- 묶어 써도 된다: `-lw`, `-cl`
- 옵션과 파일은 어떤 순서로 와도 된다 (`wc-lite a.txt -l b.txt`)
- 기준은 C 로캘의 GNU wc(`LC_ALL=C wc`)다

### 기능
- F1. 줄 수는 `\n`(0x0a) 바이트의 개수, 바이트 수는 읽은 바이트 수다. 마지막 줄에 `\n`이 없으면 그 줄은 세지 않는다
- F2. 단어 수: 바이트를 세 부류로 나눈다
  - 공백: 0x09~0x0d(`\t \n \v \f \r`)와 0x20(` `). 단어를 끝낸다
  - 단어 글자: 0x21~0x7e. 단어 밖에서 만나면 단어 수가 1 늘고 단어 안으로 들어간다
  - 그 밖(0x00~0x08, 0x0e~0x1f, 0x7f~0xff): 아무 일도 하지 않는다. 단어를 시작하지도 끝내지도 않는다
  - 예: `one\vtwo`는 2단어, `a\x01b`는 1단어, `\x01`만 있으면 0단어
- F3. 파일 하나에 한 줄: 고른 항목을 각각 폭 W로 오른쪽 정렬해 공백 1칸으로 잇고, 공백 1칸 뒤에 인자로 받은 파일 이름을 그대로 쓴다
- F4. 옵션을 준 순서와 상관없이 출력 순서는 줄 → 단어 → 바이트다. 같은 옵션을 두 번 줘도 된다 (`-l -l`, `-ll`)
- F5. 파일 인자가 2개 이상이면 마지막에 합계 줄을 쓰고, 이름 자리에 `total`을 쓴다. 합계는 읽은 파일만 더한다. 읽지 못한 파일이 있어도(모두 못 읽어도) 인자가 2개 이상이면 합계 줄을 쓴다
- F6. 폭 W (GNU wc와 같은 규칙)
  - 파일 인자가 1개이고 고른 항목도 1개면 W = 1
  - 그 밖에는 세기 전에 모든 파일 인자의 메타데이터를 본다. 일반 파일 크기를 모두 더한 값의 10진 자릿수가 W다(최소 1). 일반 파일이 아닌 것(디렉터리, `/dev/null` 같은 장치)이 하나라도 있으면 W는 최소 7이다. 메타데이터를 못 읽은 인자(없는 파일)는 빼고 계산한다
  - 폭은 내용이 아니라 메타데이터로 정한다. 수가 W보다 길면 자르지 않고 그대로 쓴다 (`/proc/version`은 메타데이터 크기가 0이라 W = 1)

### 출력 예시 (이 머신의 `LC_ALL=C wc`와 같음)
```
$ printf 'Hello, world\n' > hello.txt
$ wc-lite hello.txt
 1  2 13 hello.txt
$ wc-lite -l hello.txt
1 hello.txt
$ wc-lite -cl hello.txt /dev/null nofile
      1      13 hello.txt
      0       0 /dev/null
wc-lite: nofile: No such file or directory
      1      13 total
$ echo $?
1
```
마지막 예의 `wc-lite: nofile: …` 줄은 표준 에러다. 위 순서는 GNU wc가 오류를 쓰기 직전에 표준 출력을 flush하기 때문에 나온다. `BufWriter`를 끝에서 한 번만 flush하면 터미널에서는 오류 줄이 맨 위에 보인다. check.sh는 두 스트림을 따로 비교하므로 어느 쪽이든 통과한다.

### 오류 처리 (잘못된 입력에 패닉 금지)
- E1. 파일 인자가 없으면: 표준 에러에 `wc-lite:`로 시작하는 사용법 한 줄 (예: `wc-lite: usage: wc-lite [-l] [-w] [-c] <파일>...`), 종료 코드 1, 표준 출력은 비어 있음 (GNU wc는 표준 입력을 읽는다. 확장 참고)
- E2. 파일 하나를 못 읽으면(없음, 권한 없음, 디렉터리): `wc-lite: <파일>: <OS 오류 메시지>`를 표준 에러에 쓰고, 그 파일의 줄은 건너뛰고 다음 파일로 간다. 끝까지 처리한 뒤 종료 코드 1. 뒤에 ` (os error N)`이 붙어도 된다
  - UTF-8이 아닌 파일 이름도 패닉 없이 이 경우로 처리한다(인자는 `std::env::args_os`로 받는다, PRINCIPLES 2-5)
  - 못 읽은 파일도 메타데이터를 읽을 수 있으면 폭 계산에 들어간다(권한 없는 일반 파일의 크기도 더한다)
  - 디렉터리는 GNU wc와 다르다. GNU는 오류와 함께 `0 0 0 dir` 줄도 쓰지만 여기서는 오류만 쓴다. 폭 계산(F6)에는 "일반 파일이 아닌 것"으로 들어간다
- E3. 모르는 옵션(`-x`, `-lx`, `--lines` 등 `-`로 시작하는 나머지 전부. 단 `-` 한 글자는 파일 이름으로 본다): `wc-lite:`로 시작하는 메시지, 종료 코드 1. 인자를 모두 해석한 뒤에 세기 시작하므로 표준 출력은 비어 있다(`wc-lite a.txt -x`도)
- E4. 출력에 실패하면(`wc-lite a.txt > /dev/full`): `wc-lite:`로 시작하는 메시지, 종료 코드 1

### 제약
- std만 사용. 외부 크레이트와 unsafe는 쓰지 않는다
- 파일은 바이트(`&[u8]`)로 다룬다. `/bin/ls`처럼 UTF-8이 아닌 파일도 센다. `fs::read`로 한 번에 읽어도 된다
- 세는 부분은 `src/counts.rs` 모듈에 둔다. 공개 API는 아래와 같고, 같은 파일의 `#[cfg(test)] mod tests`에 `from_bytes`를 검사하는 `#[test]`를 3개 이상 둔다 (빈 입력, 마지막 `\n` 없음, 공백 6종을 포함. 2026-10-18 리뷰에서 명확히 함)
  ```rust
  pub struct Counts { pub lines: u64, pub words: u64, pub bytes: u64 }
  impl Counts {
      pub fn from_bytes(data: &[u8]) -> Counts; // F1, F2
  }
  ```
  합계(F5)를 더하는 방법은 자유다 (메서드, 또는 `impl AddAssign for Counts`로 `total += c`)
- 그 자리에서 처리할 수 없는 오류(E1, E3, E4)는 `Box<dyn Error>`로 `main`까지 올린다. 파일 하나의 실패(E2)는 파일 루프 안에서 처리한다 (PRINCIPLES 2-4)
- 출력은 `BufWriter`로 모으고 끝에서 직접 `flush`한다 (PRINCIPLES 5-2, E4)
- 정상 출력은 표준 출력, 오류는 표준 에러
- 기준 환경: GNU coreutils wc 9.4, `LC_ALL=C` (check.sh가 직접 설정한다)

### 완료 기준
```sh
./days/d00-wc-lite/check.sh
```
- 마지막 줄이 `FAIL 0`이고 종료 코드 0이면 완료
- `cargo test -p wc-lite`에서 counts 모듈의 테스트 3개 이상이 통과해야 한다
- 정상 케이스는 `LC_ALL=C wc`와 표준 출력·표준 에러·종료 코드를 모두 비교한다 (PRINCIPLES 6-2). 표준 에러는 `wc:`를 `wc-lite:`로 바꾸고, 내 출력 끝의 ` (os error N)`을 뗀 뒤 비교한다
- 경계값: 파일 길이 0·1, 마지막 `\n` 없음, 폭의 자릿수 경계(크기 9·10, 합 9·10, 999999·1000000), 아주 큰 파일(10⁸바이트 희소 파일), 파일 1·2·8개
- 명세가 wc와 다르게 정한 곳(E1, E2의 디렉터리, E3, E4)은 명세 기준으로 본다
- FAIL이면 그 아래 줄에 어느 쪽(stdout/stderr/종료 코드)이 어떻게 다른지 나온다

### 범위 밖
표준 입력(`-`는 파일 이름으로만 다룬다), `-m`·`-L`·`--total` 같은 다른 옵션과 긴 옵션, `--`, UTF-8 로캘의 단어 규칙, 특수 문자(공백, 따옴표, 탭, 줄바꿈)가 든 파일 이름의 따옴표 처리 (GNU는 오류 메시지에서 따옴표를 붙인다)

### 확장
- 표준 입력: 파일 인자가 없거나 `-`이면 표준 입력을 센다. 이때의 폭 규칙은 `wc < hello.txt`, `cat hello.txt | wc`, `wc - < /dev/null`로 직접 실험해서 찾는다. `EXT=1 ./days/d00-wc-lite/check.sh`로 확인
- 조금씩 읽기: `BufReader`로 64KB씩 읽게 바꾼다. 단어가 버퍼 경계에 걸쳐도 맞게 세려면 상태를 이어 가야 한다(그 테스트를 먼저 쓴다, PRINCIPLES 6-1). `fs::read` 버전과 시간·최대 메모리를 비교한다 (`--release`, 환경 기록)
