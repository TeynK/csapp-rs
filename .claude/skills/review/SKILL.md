# $ARGUMENTS 리뷰

## 1. 직접 돌려 보기
1. `days/dNN-*/check.sh`, `cargo test -q -p 패키지`, `cargo clippy -q -p 패키지`, `cargo fmt --check -p 패키지`.
2. 배울 거리로만 `cargo clippy -q -p 패키지 -- -W clippy::pedantic`도 본다(의무 아님).
3. check.sh가 놓칠 만한 경계값과 잘못된 입력을 몇 개 더 넣어 본다: 패닉, 종료 코드, 표준 에러.
4. 성능을 말하려면 `--release`로 재고 환경을 적는다.

## 2. 읽기
5. 코드 전체, README의 기록(예측·결과·배운 것), `git log`.

## 3. 피드백 (채팅, 이 순서로)
1. 총평 표: 정확성, 견고성, 구조, 성능, 이름, 관용구, 규칙 준수. 항목마다 ○△✕와 근거 한 줄.
2. 잘한 점 2~4개를 구체적으로.
3. 반드시 고칠 것: 명세 위반, 패닉, 틀린 결과. 재현 명령과 함께.
4. 원칙 위반: PRINCIPLES.md 번호로 짚는다(예: "3-4 위반: …").
5. 더 Rust다운 대안: 학습자가 이미 끝낸 코드이므로 3~10줄짜리 "이렇게 바꾸면" 예시는 괜찮다. 파일 전체를 다시 써 주지 않는다.
6. 개념 정정: README 기록이나 주석에 있는 오해.
7. 다음 할 일: 리뷰 반영 목록(필수와 선택 구분), BUGS.md에 적을 줄 제안(RULES.md 형식), `docs/SYNTAX.md`에 덧붙일 새 문법.
8. 복습 퀴즈 4~6문항: 답을 보지 말고 답하게 하고, 답이 오면 채점하고 보충한다.

빠뜨리지 않는 네 관점: 개념 오해, Rust 관용구, unsafe 건전성(`// SAFETY:`가 1순위), 성능.

## 4. 남길 것
- `days/dNN-*/REVIEW.md`에 날짜와 함께 요지를 덧붙인다: 총평 표, 필수 지적, 위반한 원칙 번호, 퀴즈 점수. 체크포인트에서 추세를 보는 근거가 된다.
- 코드와 README의 기록은 고치지 않는다.
