# $ARGUMENTS 브리핑

## 1. 준비
1. `docs/CURRICULUM.md`에서 $ARGUMENTS 항목(읽기, 개념, Rust, 만들 것, 확장)과 그 주의 "CSAPP 읽기"를 읽는다.
2. 직전 Day의 README 기록과 `REVIEW.md`를 읽는다: 예측이 맞았는지, 막힌 시간, 힌트 단계, 아직 안 고친 필수 지적.
3. 이 머신에서 필요한 도구가 있는지 확인한다(비교 대상 도구, strace, perf 등). 측정하는 날은 `lscpu`와 `uname -r`도 본다.

## 2. 참조 구현으로 명세 검증 (학습자에게 보여 주지 않는다)
4. 서브에이전트(Agent 도구)에게 맡긴다. 넘길 것: 명세 초안, 출력 예시, check.sh 초안, 작업 폴더 `/tmp/csapp-ref/dNN/`. 시킬 것:
   - 참조 구현을 파일 도구로 쓴다(Bash heredoc 금지). 이 폴더의 편집은 settings.json이 미리 허용해 두었다.
   - 빌드하고 출력 예시와 check.sh를 실제로 돌린다.
   - 돌려줄 것은 통과 여부, 실제 출력, 명세에서 고칠 점뿐이다. 코드는 돌려주지 않는다.
   - 끝나면 `/tmp/csapp-ref/dNN/`를 지운다.
5. 서브에이전트가 알려 준 고칠 점을 명세와 check.sh에 반영한다. 다 맞을 때까지 4를 반복한다.

## 3. 파일
6. 패키지가 없으면 RULES.md의 "Day 시작" 절차를 따른다(`cargo new days/dNN-이름 --name 이름`, 템플릿 복사). 명령은 학습자의 승인을 받고 실행한다. `src/`의 Hello world는 건드리지 않는다.
7. `days/dNN-이름/README.md`의 `## 명세`에 8항목을 쓴다: 목적, 사용법, 기능(F1…), 출력 형식, 오류 처리(E1…), 제약, 완료 기준, 범위 밖과 확장. `## 기록`은 템플릿 그대로 둔다.
8. `days/dNN-이름/check.sh`를 만든다(실행 권한 포함). 규칙:
   - 맨 앞에서 `cargo build -q -p 패키지`로 빌드한다.
   - 정상 케이스는 표준 출력, 표준 에러, 종료 코드를 모두 비교한다(PRINCIPLES.md 6-2). 비교할 실제 도구(xxd, wc 등)가 있으면 그것과 diff하고, 없으면 참조 구현으로 얻은 기대 출력을 스크립트에 넣는다.
   - 경계값을 넣는다: 0, 1, n−1, n, n+1, 아주 큰 값, 빈 입력.
   - 오류 케이스는 패닉 없이 명세의 메시지와 종료 코드가 나오는지 본다.
   - 마지막에 OK·FAIL 개수를 찍고, FAIL이 있으면 종료 코드 1로 끝낸다.
9. 루트 `README.md` 표에 행을 추가한다(상태 `진행 중`).
10. 개념 문서 `concepts/dNN-주제.md`를 쓴다(아래 "개념 문서" 기준). 그날 과제가 쓰는 CSAPP 절을 이 문서 하나로 익힐 수 있어야 한다. 여러 날 이어지는 주제라도 Day마다 한 파일이다.
11. 브리핑 전체를 `days/dNN-이름/BRIEF.md`에 쓴다(4절 항목 전부). 채팅은 스크롤로 다시 찾기 어려우므로 파일이 원본이다.

## 4. 브리핑 (`BRIEF.md`에 쓴다. 읽는 데 10분)
12. 복습 퀴즈 2문제: 전날 내용. 답은 쓰지 않는다. 학습자가 답한 뒤에 채팅으로 채점한다.
13. 명세 요점: README에 쓴 명세를 짧게 요약한다.
14. 개념 핵심: CSAPP 절 번호와 함께 5~10줄로 요약하고, 자세한 내용은 개념 문서로 연결한다. 책의 연습문제 1~2개를 예측에 쓴다.
15. 오늘 쓸 Rust 문법: C와 비교하고, 예시는 오늘 과제와 다른 상황으로 든다.
16. 흔한 함정 3~5개.
17. 예측 질문 2개: 구현 전에 README의 `예측:`에 적게 한다. 답은 쓰지 않는다.
18. 진행 안내: 15분 넘게 막히면 "힌트 1", 끝나면 `./days/dNN-이름/check.sh`를 돌리고 "Dn 리뷰".

채팅에는 짧게 보낸다: 준비한 것(파일 경로 3개: README 명세, BRIEF.md, 개념 문서), 복습 퀴즈 2문제, 예측 질문 2개, 첫 할 일 한 줄.

## 개념 문서 (`concepts/dNN-주제.md`)
- 이름: `concepts/d01-cache-organization.md`처럼 Day 번호와 주제. 소문자, 단어는 `-`
- 목표: 책을 읽지 않아도 이 문서만으로 그날의 "CSAPP 읽기" 절을 남에게 설명하고, 책의 연습문제를 풀 수 있는 수준. 과제에 필요한 앞 절 개념이 있으면 함께 넣는다
- 순서: 한눈에 보기(결론 5줄) → 용어 표(한국어·영어·기호) → 절 번호 순 본문(왜 → 구조 → 동작) → 손으로 따라가는 예 → 흔한 오해 → C·어셈블리와의 연결 → 이 머신에서 확인한 값 → 커리큘럼에서 다시 나오는 곳 → 확인 문제(답은 `<details>`로 접는다) → 참고(책의 절·그림·연습문제 번호)
- 그림은 ASCII로 그린다. 표는 비교하거나 정리할 때만
- 쓰지 않는 것: 그날 예측 질문의 답, 그날 과제를 푸는 코드, 책 연습문제의 답(풀이 방법은 설명해도 숫자 답은 쓰지 않는다)
- 이 머신의 수치(캐시 구성, 측정값)는 실제로 확인한 것만 쓰고 출처 명령을 적는다(CLAUDE.md 규칙 3)

## 주말 ★ 유닛
- 명세를 단계(마일스톤)로 나누고, 단계마다 중간 리뷰를 받게 한다.
- 마지막 30~60분은 그 주의 "코드 리딩" 항목을 질문 하나와 함께 안내한다(CURRICULUM.md "대형 코드 읽는 법").

## 하지 않는 것
- 정답 코드, 함수 몸통, 그날 과제를 그대로 푸는 예시. `BRIEF.md`와 개념 문서에도 마찬가지다.
