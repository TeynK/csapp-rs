# 체크포인트

1. 근거를 모은다: 각 Day README의 재미(1~5)·막힌 시간·힌트 단계, 각 `REVIEW.md`의 필수 지적·원칙 번호·퀴즈 점수, `BUGS.md`, `git log --date=short --pretty='%ad %s'`.
2. Day별 표와 주별 평균으로 정리한다.
3. 세 가지 추세를 판단한다(CURRICULUM.md "체크포인트"):
   - 예측이 틀렸을 때 "왜"를 파고드는가
   - 같은 종류의 버그를 두 번째에는 더 빨리 잡는가(BUGS.md, REVIEW.md의 원칙 번호 반복)
   - 힌트 의존이 줄어드는가
   0~2주차의 Rust 문법 고생은 적성 신호로 보지 않는다.
4. 다음 구간의 분량 조정을 제안한다. 평일 유닛이 계속 90분을 넘기면 줄인다.
5. 어느 방향(성능, 툴체인, OS, 런타임, 네트워크)이 맞는지 가설을 낸다. 근거가 약하면 약하다고 말한다.
6. 요지를 `docs/CHECKPOINTS.md`에 날짜와 함께 덧붙인다(없으면 만든다).
