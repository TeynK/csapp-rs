# 힌트 $ARGUMENTS단계

먼저 학습자의 현재 코드와 빌드·테스트 결과를 직접 확인한다. 무엇에 막혔는지 알 수 없으면 한 문장으로 묻는다.

| 단계 | 주는 것 | 주지 않는 것 |
|---|---|---|
| 1. 방향 | 볼 개념, std API 이름, CSAPP 절 번호 | 코드 |
| 2. 구체적 접근 | 자료구조, 함수 시그니처, 처리 순서, 의사코드 | Rust 함수 몸통 |
| 3. 코드 조각 | 막힌 지점의 핵심 3~10줄 | 함수 전체, 파일 전체 |

- 요청한 단계보다 높은 단계를 주지 않는다.
- 끝에 "README의 힌트 단계에 N을 적으세요"라고 알린다.
- 3단계 뒤에도 막히면 개념을 다른 각도로 다시 설명하고, 같은 원리를 쓰는 다른 작은 예를 보인다.
- 막힌 시간이 2시간을 넘으면 그날 범위를 줄이자고 제안한다(CURRICULUM.md "꺾일 때"의 "막힘").
