# 저장소 규칙

애매하면 멈추지 말고 가까운 쪽으로 정한 뒤, 필요하면 이 파일을 고친다.

## 폴더

| 폴더 | 담는 것 | 쓰는 사람 |
|---|---|---|
| `crates/이름/` | 마일스톤을 넘어 쌓이는 라이브러리(cachesim, elf, sysx, alloc …) | 골격은 튜터, 핵심은 학습자 |
| `apps/이름/` | 실행 파일(csim, elfdump, tsh, tiny, proxy …). CLI는 튜터가 쓴다 | 튜터, 학습자 |
| `experiments/` | 실험용 패키지 하나. 실험마다 `src/bin/이름.rs` | 튜터, 학습자 |
| `concepts/` | 개념 문서 `chNN-k-주제.md` | 튜터 |
| `milestones/mN-주제/` | `README.md`(명세), `LOG.md`(기록), `QA.md`(질문 노트), `REVIEW.md`(리뷰), `results/`(측정 결과) | 아래 "기록" |
| `papers/` | 논문 세션 기록 `mN-주제.md` | 튜터, 학습자(노트) |
| `docs/` | `CURRICULUM.md`, `RULES.md`, `GLOSSARY.md` | 튜터 |
| `labs/` | CMU 핸드아웃. 커밋하지 않는다(.gitignore) | — |
| `scratch/` | 1MB가 넘는 생성물(트레이스, 큰 테스트 파일). 커밋하지 않는다 | — |

- 패키지는 `cargo new --lib crates/이름` 또는 `cargo new apps/이름`으로 만든다. 루트 `Cargo.toml`의 `members`에 자동으로 추가된다.
- `members`에 패키지가 없는 glob(`crates/*` 같은)을 넣지 않는다. 맞는 패키지가 없으면 cargo가 워크스페이스 전체를 읽지 못한다(cargo 1.99.1에서 확인).
- 통합 테스트는 패키지의 `tests/`, 테스트 입력은 `tests/data/`에 둔다.
- 측정 결과(작은 CSV, PNG)는 그 마일스톤의 `results/`에 둔다.

## 이름

- 식별자는 `docs/GLOSSARY.md`를 따른다. 사전에 없는 이름이 필요하면 튜터가 사전에 먼저 적는다.
- Rust 관례: 파일·모듈·함수·변수는 `snake_case`, 타입·트레잇은 `UpperCamelCase`, 상수는 `SCREAMING_SNAKE_CASE`.
- 식별자는 영어, 주석과 문서는 한국어.
- 패키지 이름은 한 단어 소문자(`cachesim`, `elfdump`).
- 개념 문서는 `concepts/ch06-2-cache-organization.md`처럼 장 번호(두 자리), 그 장 안의 순번, 주제로 짓는다.
- 마일스톤 폴더는 `milestones/m1-memory-hierarchy/`처럼 번호와 주제로 짓는다.

## 기록

| 파일 | 칸 | 쓰는 사람 |
|---|---|---|
| `LOG.md` | 예측 | 학습자(실행 전) |
| `LOG.md` | 결과와 피드백, 배운 것, 힌트 단계 | 튜터 |
| `LOG.md` | 재미(1~5), 막힌 시간(분) | 학습자 |
| `QA.md` | 질문과 답의 요지 | 튜터(세션 중에 바로) |
| `REVIEW.md` | 리뷰 | 튜터 |

- 날짜는 `YYYY-MM-DD`로 쓴다.
- 측정한 기록에는 환경 한 줄을 붙인다: CPU 모델(`lscpu`), 커널(`uname -r`), 빌드(`--release`).
- 버그를 잡으면 "배운 것"에 `버그: 증상 → 원인 → 교훈` 한 줄로 남긴다.

## 커밋

- 커밋과 push는 학습자가 한다. 튜터는 메시지를 제안한다.
- 형식은 `영역: 한 일`이고, 한 줄 요약은 50자 안팎이다.
  - 단계 작업은 `M1-2`, 저장소 설정과 문서는 `repo`
  - 예: `M1-2: 골격`, `M1-2: CacheSet::access`, `M1-2: 리뷰 반영 - 축출 순서`
- 튜터가 준 골격은 학습자가 먼저 `Mn-k: 골격`으로 커밋한 뒤 작업한다. 그래야 이력에서 골격과 학습자의 코드가 갈리고, 리뷰가 그 차이를 본다.
- 미완성도 커밋한다. 컴파일이 안 되면 끝에 `(WIP)`를 붙인다.
- 브랜치는 `main` 하나다.

## 코드

- 커밋 전(WIP 제외): `cargo fmt` → `cargo clippy -q --workspace` 경고 0. 둘 다 학습자가 돌린다.
- 모든 `unsafe` 위에 `// SAFETY:` 주석을 단다(clippy가 검사한다).
- 사용자 입력이 닿는 경로에는 `unwrap()`·`expect()`를 쓰지 않는다. 테스트, 그리고 실패할 수 없는 게 자명한 곳만 허용한다.
- 외부 크레이트는 루트 `[workspace.dependencies]`에 버전을 적고, 멤버는 `이름.workspace = true`로 가져온다. 쓸 수 있는 크레이트는 `docs/CURRICULUM.md`의 "크레이트 정책"을 따른다.

## 설계 원칙

리뷰의 설계 조언은 이 번호로 짚는다.

1. `main`은 조립만 한다. 계산은 라이브러리에, 입출력은 가장자리에 둔다.
2. 입력과 출력은 인자로 받는다(`impl BufRead`, `impl Write`). 그래야 파일 없이 테스트할 수 있다.
3. 처리할 수 없는 오류는 `?`로 올린다. 오류 종류는 enum으로 나누고, 메시지는 `Display` 한 곳에서 만들며 맥락(무엇을 하다가, 어디서, 왜)을 담는다.
4. 패닉은 내 버그에만 쓴다.
5. 인자는 빌리고 반환은 소유로 한다. 검사가 끝난 값은 타입이 보장하게 한다.
6. `unsafe`는 작은 함수 안에 가두고 안전한 API로 감싼다. 지켜야 할 불변식은 `// SAFETY:`에 쓴다.
7. 반복 루프 안에서 할당하지 않는다. 출력은 모아서 쓰고, 끝에서 `flush`한다.
8. 추측하지 말고 측정한다.
9. 버그를 고치기 전에 그 버그를 잡는 테스트부터 쓴다.
